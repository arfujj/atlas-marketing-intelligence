# Decision log

Non-obvious decisions taken while building ATLAS, each with the alternatives considered and
the reason. Numbered in the order they were made. The owner was not available for questions,
so every judgement call is recorded here.

| # | Decision | Alternatives | Reason |
|---|---|---|---|
| D-001 | All builds, model fits and the Criteo download ran on the machine the build agent was given, which turned out to be the owner's Mac mini (10 cores, ~21 GB free disk), not a cloud VM. A probe for a remote environment also resolved to the same machine. Footprint was kept small: Python env via uv (hard-linked from the existing cache), raw Criteo file kept compressed outside the repo and deleted after the aggregated results were written, posterior draws thinned before committing. | Stop and wait for a cloud environment; skip heavy steps | The brief could not be finished without compute, no cloud machine was reachable, and the disk budget could be respected by never decompressing raw data and cleaning up regenerable artifacts. |
| D-002 | Python pinned to 3.12 with `.python-version`. | Use the system 3.13 | The brief specifies 3.12; uv otherwise picked the Anaconda 3.13 interpreter. |
| D-003 | Simulator v0.2 components (sessions, incidents, journeys) use independent child RNG streams `default_rng([seed, k])`. | Draw from the main stream | Keeps every v0.1 draw identical, so the pre-registered numbers (naive OLS $17.81/$ on brand search) are reproduced exactly with incidents off. Verified by test. |
| D-004 | The checkout incident is placed in the final history week (2026-09-21). | Somewhere mid-window | Makes "why did revenue fall last week?" a real question with a known answer, which exercises the anomaly engine and the analyst at the most recent date, where operators actually look. |
| D-005 | Observed media `spend` is *billed* spend; methods are graded against `true_roi_first_order_billed` (true incremental first-order revenue per billed dollar). | Grade against ROI per effective dollar | An analyst only sees billed spend. During the CPC spike the extra billed spend buys nothing, so the honest truth for "revenue per dollar spent" is per billed dollar (differs by 1.1% for non-brand search, 0 elsewhere). |
| D-006 | Journeys down-weight organic/direct touches (×0.25 of organic sessions) and include a weighted sample of non-converting journeys (2 per converter, weight 25). | Converting paths only; no organic touches | Markov removal effects are undefined without non-converting paths. Sampling with weights keeps the file ~11 MB instead of ~250 MB while keeping transition probabilities consistent. |
| D-007 | The MMM is written directly in PyMC (own model code), not with PyMC-Marketing's `MMM` class. The strategy doc's stack table named PyMC-Marketing; the build brief supersedes it. | PyMC-Marketing wrapper; Meridian | Full transparency of priors, the ROI parameterisation and the lift-test likelihood term, which are the parts interviewers probe. |
| D-008 | Site sessions are not used as an MMM control, even though in this simulator organic sessions are a clean proxy for baseline demand. | Use organic sessions as a demand control | In real data organic/direct sessions are partly *caused by* media (a mediator), so controlling for them biases media effects toward zero. Using them here would exploit a simplification of the simulator rather than demonstrate a transferable method. |
| D-009 | GA4 daily marts use UTC dates; sessions are dated by their first event and counted once. | Property timezone (America/Los_Angeles); split sessions across days | In this export `event_date` equals the UTC date of `event_timestamp` for 100% of rows (checked against LA/NY/Denver: 67–79% match), so UTC is the export's own convention. Counting a midnight-crossing session on both days would inflate sessions by 845. |
| D-010 | GA4 channel grouping is derived from `first_user_medium` and every column carries the `first_user_` prefix; a dbt test forbids unprefixed source/medium/channel columns in GA4 marts. | Present it as session source; drop it | It is the only acquisition field in the sample; the prefix and the test keep it from being read as session or last-touch attribution. |
| D-011 | GA4 dedup rule: keep the earliest purchase event per valid `transaction_id` (ties: higher revenue, then row id). `(not set)`/NULL ids are kept as *unidentified* events, excluded from headline revenue and shown separately ($31,817, 906 events). Headline deduplicated revenue = **$307,640**. | Keep the latest or the max-revenue event; add unidentified events to revenue | The earliest event is the original tag fire; later rows are re-fires. Unidentified events cannot be deduplicated, and most of them come from two instrumentation episodes (2–11 Nov 2020 and from 26 Jan 2021), so adding them would mix in measurement error. The previously quoted $307,608 could not be reproduced by any rule and was corrected. |
| D-012 | GA4 RFM: recency and monetary as quintile scores, frequency as a raw bucket (1, 2, 3+), six rule-based segments; 92-day window only. | Frequency quintiles; k-means; CLV model | 88% of buyers purchase once, so frequency quintiles are degenerate; rules are explainable; the strategy excludes CLV forecasting on 92 days. |
| D-013 | Halden anomaly thresholds are calibrated per series family (national, region, channel) on 12 incident-free simulated worlds at a 0.5% false-alarm rate per series-week, and precision/recall are measured on 12 *different* worlds with random incidents. | Fixed \|z\| ≥ 3.5; calibrate and evaluate on the same worlds | Calibrating on the evaluation worlds would overstate precision. Separate seeds make the reported figures out of sample. |
| D-014 | When a conversion drop is site-wide, the engine does not also offer "measurement failure in region X" for the regions that happen to cross the threshold. | Report every rule that fires | Found on the flagship checkout week: the site-wide drop pushed R04/R07 past the regional cut-off and produced a misleading second hypothesis. One cause, one explanation; the regional evidence is still in the shift-share table. |
| D-015 | The multi-world scorecard uses the flagship sampler settings (4 chains × 2,000 tune × 2,000 draws), not a lighter 3 × 1,000 run. | Keep the faster run; report anyway | The light run converged (R-hat < 1.01, no divergences) in 0–25% of fits per variant; ROI conclusions were similar but numbers from unconverged fits are not defensible. At full settings 79–96% of fits converge and none diverge; the unconverged remainder is reported, not dropped (run scorecard-24w-9a760623). |
| D-016 | Uplift rankings break tied scores at random (`rank_order`). | Stable sort | The evaluation rows keep file order; tied X-learner scores then came out treated-first and bent the Qini curve (a straight-line dip from ~63% to ~82% targeted), understating the X-learner. Found from the chart in the web app; a regression test now covers it. |
| D-017 | The next-best-experiment card ranks candidate tests by net value (value of information minus expected test cost), not by value of information alone. | Rank by EVSI | Pausing an over-invested channel has *negative* expected cost (spend saved exceeds revenue lost). Ranking by EVSI alone recommended a test with −$12K net value over one with +$21K. |
| D-018 | API responses are typed by hand in `web/src/lib/types.ts`; request bodies are generated from OpenAPI. | Pydantic response models for every endpoint | Most endpoints serve stored run JSON whose shape is pinned by the Python contract tests; full response models would duplicate those schemas. Revisit if the frontend grows. |
| D-019 | The web app keeps Next 16's Cache Components on: each page is a static shell with the data section streamed inside `<Suspense>`. | Turn Cache Components off; mark routes dynamic | The shell (navigation, provenance banner) renders instantly and API latency only affects the data region. |
